Asset check

The gate. Nothing goes on a phone until it passes this.

Drop a .glb here and this page opens it: the header, the JSON chunk and the binary chunk. It counts what is actually inside: triangles, textures, and their real pixel dimensions. The file is read on this device. Nothing is uploaded.

The budget, and why each number exists

LimitWhy
≤ 100,000 trisAbove this a mid-range Android starts dropping frames, and dropped frames read as broken tracking even when tracking is fine.
≤ 2048 pxA 4096px texture is four times the memory of a 2048px one and looks identical on a phone held at arm's length. It is a common and avoidable source of file weight.
≤ 10 MBThe file is typically opened on mobile data, in a shop, while standing. Beyond roughly 10 MB, abandonment rises sharply.
≤ 8 sTime from tap to visible content. Beyond eight seconds most users abandon the page. This figure is measured with a stopwatch rather than by a parser.

What to do when it fails

FailureFix, in order of least damage
Too many trianglesDecimate in the tool that made it (Polycam and Scaniverse both export a lower-poly option). Crop away the floor and background the scan picked up. Usually half the mesh is room, not product.
Texture too largeResize the texture image to 2048 or 1024 and re-export. For a small object on a shelf, 1024 is plenty.
File too heavyFix the two above first; they are usually the whole story. Then check for a second unused texture set riding along.
Too many meshesMerge. Each separate mesh is another draw call, and draw calls are what actually kill phone framerate.
